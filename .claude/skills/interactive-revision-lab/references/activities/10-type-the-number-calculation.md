# Activity 10: Type-the-Number Calculation (interactive-revision-lab)

Shared rules (headings, no capitals, checklist, verification) are in SKILL.md; the engine helpers, layout and equations are in the `workout-page-shell` skill.

For any "work this out" question with a single numeric answer (a worked example, a value read off a graph, a formula rearrangement) — the student types a number rather than dragging or revealing. Shared building blocks, generalized across three different uses in the Forces Lab (worked examples, graph-reading questions, and a calculate tab):
- **Tolerance helper** `numClose(val, answer)`: `tol = Math.max(0.05, Math.abs(answer)*0.02)` — 2% relative tolerance with a 0.05 absolute floor, so it "accepts a range of significant figures" instead of demanding an exact string match or an unreasonably tight fixed epsilon.
- **Shared CSS class family** `.calc-inputs / .calc-input-row / .calc-input-label / .calc-input-wrap / .calc-num-input / .calc-input-unit / .calc-fb`: one visual language for every numeric-input question in the lab (label on the left, a bounded-width `<input type="number">`, the unit shown alongside — not inside — the input, feedback text below). Reuse the same classes everywhere rather than styling each numeric block separately.
- **Factory shape**: `cfg = {el, idPrefix, questions:[{label, unit, answer}]}` → renders one `.calc-input-row` per question plus a single "Check" button; grading loops the questions, applies `numClose`, marks each row correct/incorrect (correct rows lock, matching the tentative+check convention). Exposes `{getState, setState}` — no `render`, since `setState` writes values directly onto the existing inputs (see "Per-viewer state" in the `workout-page-shell` skill).
- **Layout**: two questions per row on wide screens, each row in its own light box (see "Layout" in the `workout-page-shell` skill); one column on phones. The "Show full working" `<details>` uses stacked fractions and substitute-then-rearrange order.
- Keep the question wording free of unnecessary hints (e.g. don't add a parenthetical telling the student to ignore sign/direction unless that's genuinely part of the skill being tested) — say only what's needed to disambiguate the expected unit/quantity.
- **Two questions per card, then New problems (Alex, 11 Nov 2026).** A Calculate card normally has exactly 2 questions, and the New problems button gives a new pair with different values *and* different properties: the context (object, material, person), and which quantity is the unknown.
  - **Question 1 always needs a rearrangement.** The unknown is never the subject of the equation as learnt: from ρ = m/V ask for m or V, never ρ; from v = fλ ask for f or λ; from P = IV ask for I or V.
  - **Question 2 is harder**: a power or root (r in Snell's law with sin⁻¹, v from KE = ½mv² or from v² = u² + 2as), a unit change (minutes to seconds, cm² to m², g to kg, °C to K), a prefix multiplier (k, M, m, G), a minus sign (deceleration, a rebound, a velocity to the left), or two equations in a row. Give it `hints:[…]`, one step each.
  - **Write each question as a generator** `rnd=>({q,unit,answer,working,hints})` that first picks a variant (which quantity is unknown) and a context, then the values from lists with `calcPick`, looping until the answer is tidy. Build the card with `calcFix(gen, seed)`, which makes the fixed first set from the generator and adds it as `make`: `calcAct(tab,title,intro,[calcFix(q1,1),calcFix(q2,2)])`. Try a few seeds and keep the ones whose first pair reads well.
  - Match each context to sensible values (no 400 K freezer, no 2.4 m³ bicycle pump, no 12 V floor sander), and pick `a`/`an` from the number (an 8 kg, an 18 V, a 180 N).
  - Write numbers with the engine's `calcNum()` (no float noise, a real minus sign, spaced thousands). In the working, no × between a number and a symbol (`2500a`, `0.4F`), and write `v₂` not `1v₂` when the coefficient is 1.
  - A question that needs a diagram (a beam, a plank, a circuit) carries it inside its own `q` text, so New problems redraws it (models: 1d Balance the beam, 2c Two resistors in series).
  - Cards whose numbers come from one fixed graph, table, trace or animation (Read the graph, Work out the numbers, Resistance from the graph, stopping distance, nuclear-equation balances) are exempt and keep their questions.
  - Check with `python3 tools/calc-check.py page.html` (16 New problems sets per card), then read about ten generated pairs yourself: the checker only checks consistency, not wording or sensible values.
