# Activity 2: Sort and Drag (sort into labelled bins) (interactive-revision-lab)

Shared rules (headings, no capitals, checklist, verification) are in SKILL.md; the engine helpers, layout and equations are in the `workout-page-shell` skill.

Generalized `createSortGame(cfg)` factory: `cfg = {poolEl, binsEl, scoreEl, items:[{id,text,cat,svg,big}], cats:[{id,label,hint,colorVar,softVar}]}`, returns `{init, render, check, reset, getState, setState}`. Reuse this same factory for every 2-4-category sort in the lab (e.g. "which process is this", "true or false", "conductor or insulator", "contact or non-contact force", "vector or scalar") — it's the same drag/pool/bin/check mechanic every time, just different data. Bin count sets a `.bins-2/-3/-4` CSS grid class that collapses responsively. **Layout default: put the bins above the pool**, not below — the student reads the categories first, then the items to sort, which matches how they'll actually scan the task; also give same-role items (e.g. all force-type cards) a shared `min-height` (see "Uniform card/item height" in the `workout-page-shell` skill) so a two-line label and a one-word label don't render at visibly different heights. Clicking a placed (unlocked) item must send it straight back to the pool (see "Every filled-but-unlocked slot" in the `workout-page-shell` skill) — don't require a select-then-click-background flow. Check every card fits its bin label exactly ("Take readings over a wide range" does not belong under "More accurate readings"; the bin became "Better results").
