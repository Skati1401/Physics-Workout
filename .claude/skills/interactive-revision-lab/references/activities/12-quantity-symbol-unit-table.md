# Activity 12: Quantity–Symbol–Unit Table (interactive-revision-lab)

Shared rules (headings, no capitals, checklist, verification) are in SKILL.md; the engine helpers, layout and equations are in the `workout-page-shell` skill.

Matches the "a) section" table format used at the start of every IG topic: four columns **Quantity, Symbol, Unit, Unit Symbol** (use "quantity" in the UI, not "property" — that's the exam-board term; "property" is for material characteristics like density/conductivity, not a measurable quantity with an SI unit). This is harder than it first looks: **exactly ONE cell per row is given, and the other THREE are blanks the student must drag in** — not the reverse. That makes which cell to reveal the entire design decision, since the given value has to uniquely pin down the row or the other three blanks have no single correct answer.
- **Picking the given cell per row — do this deliberately, not by rotating columns for variety**: rank candidates by how safe they are as a sole clue. **Quantity name** and **full Unit name** are almost always safe (too specific to collide with anything else). **Unit Symbol** is usually safe (N, Pa, kg each tie to one quantity) but still needs checking against every other quantity in *this* table. **Bare Symbol is the riskiest** — many single letters are legitimately reused for different quantities or sub-cases, so a bare symbol is only safe as the given cell if it doesn't collide with anything else in play.
- **Known IG symbol collisions to check against** (same letter, genuinely different correct quantities — this list is reusable across topics, not just mechanics): **p** (pressure / momentum), **u / v** (initial / final velocity — don't give a bare "velocity" row at all unless the table only ever needs one of the two; label it "initial velocity"/"final velocity" if both appear), **m** (mass / milli- prefix), **s** (displacement / second), **a** (acceleration / area), **t** (time / temperature), **W** (work done / weight — don't put both in the same table), **V** (volume / voltage), **g** (gravitational field strength or free-fall acceleration / the unit gram). Also check across columns, not just within the Symbol column — e.g. giving bare "A" as area's symbol is only safe if no other quantity in the same table has unit symbol A (ampere/current) too, since a student could misread which column a bare letter is answering for.
- If a row's only safe clue is the Quantity name itself, give the Quantity — don't force column variety at the cost of making a row unsolvable. Variety across rows is a nice-to-have, correctness is not negotiable.
- Build on the same chip-pool/blank mechanic as Fill in the Blank (pattern 1) rather than a new factory: one shared pool holding quantity names, symbols, unit names, and unit symbols all mixed together (since any of those four types can be the thing being blanked depending on the row), each tagged with which specific blank it resolves so a correct chip only locks the one slot it belongs to even when another row's correct answer happens to share the same text (e.g. two different rows both correctly needing "N").
