# Activity 11: Label the Graph Line (interactive-revision-lab)

Shared rules (headings, no capitals, checklist, verification) are in SKILL.md; the engine helpers, layout and equations are in the `workout-page-shell` skill.

For a plotted line graph (displacement/velocity/time or equivalent) where the task is to identify what's physically happening at different points along the line — not a separate list of rows next to the chart, but draggable caption chips dropped directly ONTO the line at the relevant point, which reads as much closer to how the graph is actually interpreted.
- **Graph rendering**: `lineGraph(o)` — an SVG line renderer built on shared dimension constants `GDIM = {W,H,padL,padR,padT,padB}`, supporting `o.yMin` for graphs that dip below zero and `o.hideSectionTags` to suppress a top-of-chart A/B/C/D legend when on-line markers replace it.
- **Anchor math**: `valueAtX(points, x)` linearly interpolates the plotted value at any x along a piecewise-straight line; `graphXAt`/`graphYAt` convert data coordinates to pixel/percent position inside the SVG's `viewBox`; `graphSectionAnchors(o)` combines these to return `{sectionId: {xPct, yPct}}` — the exact on-line position for each labelled section's midpoint.
- **Drop targets**: a positioned `.graph-plot-wrap` (percentage-based, so it scales with the SVG regardless of rendered size) holds one `.graph-line-drop` per section, absolutely positioned via inline `left/top` from the anchor percentages; each renders a small lettered `.drop-marker` circle plus a `.drop-caption` that appears once filled (flip the caption above vs. below the marker — e.g. via a `yPct` threshold — so it doesn't run off the top/bottom of the chart). Truncate long chip text for the caption (`truncateWords(s, ~34 chars)`) since the on-line space is tight. Put the caption pool in a column to the right of the graph on wide screens (a two-column grid, graph about 640px, stacking under about 860px) so students can see the whole graph and every caption at once.
- **Wording — this is the part most likely to go wrong**: caption chips must name the *physics meaning* of that section ("Increasing velocity", "Constant deceleration", "Stationary") and never a *shape description* ("curving upward", "flat", "sloping down") — a shape word lets the student match purely by eyeballing the picture against the obviously-matching visual, which isn't a test of understanding. Apply the same rule to distractor chips.
- Follow the on-line labelling task with a numeric Task 2 using pattern 10 ("work out the acceleration/distance for section B") so the same graph is used for both identification and calculation.
- For a topic with two related graph types (e.g. s–t and v–t), give each its own tab rather than combining them — see the tab-splitting note in Page Shell.
