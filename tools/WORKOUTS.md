## 1. Calculations and Graphs sets (start now, Forces Part 1 only)

- [x] **How the sets work (27 Oct 2026):** the workouts are never changed. `tools/sets/build.py` copies the chosen workout sections into each set page and keeps only the activities of that set's kinds (Calculate and Spot the error; Label the graph and Calculate). Each set has its own saved answers. A GitHub Action (`.github/workflows/build-sets.yml`) re-runs the script on every push to `main`, so a fix to a workout reaches the sets a minute or two later. To add a tab, add a line to `SETS` in `build.py`.
- [x] **Calculations becomes a chooser (12 Nov 2026, Alex):** `calculations.html` has no tabs. It lists one row per equation (31 rows since 12 Nov 2026: no R = R₁ + R₂, kelvin or Unit 7; every row starts ticked, and Start is at the top; by unit, TA from the workout tab's own `data-ta`); a student ticks rows (or a whole unit, or Tick all; Leave out TA hides the TA rows) and Start shows those rows' Calculate cards one after another (Mix the order shuffles them). The rows are `SETS['calculations.html']['rows']` in `build.py`: unit, id, label, equations (`[[top|bottom]]` fractions), and the cards as ('src-tab', the card's title as written in the workout); `'sources'` says which workout section each 'src-tab' comes from. The build stops if a card title is no longer in its section. Graph-reading Calculates (Read the graph, Work out the numbers, stopping distance, Resistance from the graph, the oscilloscope) are left for the Graphs page. Ticks, Mix, Leave out TA and the open view are saved under `set-calculations-v2-pick`; answers under `set-calculations-v2`. Each row counts as a GoatCounter event (`calculations#<row id>`) when a student starts it. Also fixed in `build.py` for both sets: each copied section runs in its own try/catch (one 6b layout error had emptied every tab after it), a section's `#panel-<tab>` lookups point at the set's panel, data a section takes from an earlier section of its page (7a `EQ_BETA`) is copied in, and the engine's own functions are never copied from a source page.
- [x] **Calculation Generator (12 Nov 2026, Alex):** `calculation-generator.html`, a hand-written page (edit it directly; it is not built by `build.py`), in the Calculations & Graphs section. 32 equations (12 Nov 2026, Alex: no R = R₁ + R₂ or kelvin row, as °C to K is a unit conversion; no Unit 7), all ticked to start, Start at the top. Its questions are its own, not the workouts' cards. `EQS` lists the equations: most are kind `'m'` (L = R, each side factors over factors, e.g. `L:['p1'],LD:['T1'],R:['p2'],RD:['T2']`), solved and worked generically by `mSolve`/`mWork`; seven are their own kind with `vals`/`work` (`SP`: a = (v − u)/t, v² = u² + 2as, F = (mv − mu)/t, Snell, critical angle, kelvin, series resistors). Each context gives a sentence (no values in it) and SI value lists; `d` is worked out, kept only when tidy (3 s.f.) unless Significant figures is on. `FAM` says how each kind of quantity may be shown: `conv` (Unit conversions: g, cm, km, min, h, km/h, cm², cm³, °C, %) and `pre` (Multipliers: kW, MJ, kV, mA, ms, kΩ, MHz, nm…). A given value is converted or prefixed only when it stays a tidy number; the answer is sometimes asked for in a converted or prefixed unit. Significant figures (Alex, 12 Nov 2026): each measured value is nudged (about ±8%, temperatures ±3%) and written to 2 or 3 s.f. with no doubt about how many (`dispSF`, keeping trailing zeros: 2.50, 0.0340); the question says "Give your answer to an appropriate number of significant figures"; the answer goes to the fewest s.f. in all the data shown, never fewer than 2, and up to the fewest in the nudged values is also accepted (so 230 V read as 3 s.f. is fine). Take g, c and whole numbers of turns are not counted; turns are never the unknown with this option; a nudge that breaks the story (order of two values, the sign of the answer) is thrown away and the question made again. Saved under `calc-generator-v1` (ticks, options, right-first-time counts per equation). To add an equation, add it to `EQS` with two or three contexts; a Playwright check that types the working's last line into 400 questions is the way to test.
- [x] **Multi-step Workout (13 Nov 2026, TODO 3e):** `multi-step.html`, hand-written (edit it directly; not built by `build.py`), in the Calculations & Graphs section, with the Calculation Generator's chooser, helpers and look. `KINDS` lists 31 kinds of problem by unit, each with `label`, `chain` (the equations in order, shown in the chooser), `ta`, `src` (the Question Index parts it is modelled on: the parts with Calc type "Multi-step", 144 on 13 Nov 2026) and `gen(rnd)`, which returns the question `q`, the `given` lines and `steps`. A step is `S(ask, unit, eq, f, work, opts)`: `f(p)` works its value from the earlier steps' values `p`, so it gives both the right value and the one that follows from the student's own earlier answers (error carried forward); `work(p,x)` writes its lines of working; options `abs` (sign not marked, e.g. deceleration, change in momentum), `pct` (a percentage) and `si` (the factor to the base unit, for the "give it in mA" message). A gen returns null to throw away awkward values. The contexts and numbers are new, never a past-paper question. Check marks every filled step; a right final answer earns every step; Show answer per step; working: givens || each step, 4 s.f. on the way and 3 s.f. for the answer. Options Show the steps (on) and Show the equations (off; Hint reveals them one step at a time). Saved under `multi-step-v1` (options, right-first-time counts per kind; ticks reset on each visit). To test: generate a few thousand problems per kind in Node (no NaN, no zero or negative values unless `abs`), then a Playwright run that types each step's last working line into 150 problems.
